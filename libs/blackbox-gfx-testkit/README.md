# blackbox-gfx-testkit

Test support for renderers behind [`blackbox-gfx`](../blackbox-gfx): synthetic scenes, image metrics and
image digests. It depends only on `blackbox-gfx` and `glam` (no wgpu, no Bevy, no window system), so any
renderer can be checked with it, and it builds in a plain `cargo test`.

Everything is procedural. There is **no game data** and no image file here: textures, meshes and scenes are
generated by code, and expected results are Rust constants (the leak check refuses `.png`).

## Scenes

`SceneId` names the scenes. `capture_scene(backend, scene, [width, height])` builds one through a
`&mut dyn RenderBackend`, captures a frame with the backend's current graphics settings, releases the
scene's resources and returns the `RgbaImage`. It polls `poll_capture`, rendering a frame between polls, so it
also works for a backend that needs a few frames per capture.

| Scene | What it checks |
|---|---|
| `Grid` | opaque ground with BC1 and RGBA textures, vertex colours, a fog ramp, lit boxes |
| `AlphaCards` | alpha-tested foliage cards, overlapping and crossing, in front of a wall |
| `BlendStack` | alpha-blended and additive quads in submission order; an additive quad hidden behind the wall |
| `SkyDome` | a sky dome 9.7 km away behind fogged ground and buildings (infinite far plane) |
| `DepthProbe` | quads from 2 m to 9 km that cross or sit 0.1 % apart: reverse-Z precision |
| `GlossySphere` | two glossy spheres, the lighting rig and the environment |
| `Effects` | the effect layer: ground surfaces, soft particles, glows, streaks, textured effects |
| `Ui` | the 2D UI layer: panels, a translucent overlay, a texture, a clip rectangle, vertex colours |

A BC1 texture is uploaded as BC1 when `capabilities().compressed_bc` is set and as the same pixels in RGBA8
otherwise, so the picture does not depend on the adapter.

## Comparing two renderers

`compare(a, b, &Mask)` returns an `ImageDiff { max, mean, p99, pixels }` over the red, green and blue samples,
optionally limited to (or excluding) rectangles. `SceneId::fidelity()` gives the class of tolerance two
different renderers should meet on a scene, `Fidelity::tolerance()` the numbers (out of 255):

| Fidelity | Scenes | Tolerance |
|---|---|---|
| `Strict` | grid, alpha cards, sky, depth | max 4, mean 0.5, p99 2 |
| `Glossy` | glossy sphere | mean 1.5, p99 8 |
| `Blended` | blend stack, effects | mean 4, p99 24 (gamma against linear blending) |
| `Ui` | ui | max 1 |

## Guarding one renderer against itself: digests

A `Digest` is the mean colour of each cell of a 32x18 grid (576 cells, 3456 hex characters). It is small
enough to keep as a Rust constant and fine enough that a visible change moves some cell.
`Digest::compare(&expected, tolerance)` reports the worst cell and how many are over a per-channel tolerance.
`Digest::to_const(name)` prints a ready-to-paste `pub const NAME: &str = "..."`.

Digests depend on the GPU and driver, so a test that uses them must be told where they were recorded. See
`blackbox-render`'s `docs/testing.md` section for the native renderer's tests and how to regenerate.

## Rules

- No game data, no binary or image files. Scenes stay under the 500-line file limit.
- Scenes are deterministic: nothing random, nothing time-dependent.
- A scene creates its resources through the trait and `release` destroys them, so one backend can run
  scene after scene.
