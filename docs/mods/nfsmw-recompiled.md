# NFSMW-Recompiled (madelrandel-blip)

## Summary

NFSMW-Recompiled is a static native recompilation of *Need for Speed: Most Wanted* (2005). The project translates the game's PowerPC code ahead of time into C++ and builds it as a native x86-64 Windows binary. It is built on the ReXGlue SDK, which supplies the Xbox 360 kernel calls, filesystem, audio, input and a Direct3D 12 translation of the Xenos GPU. It is not an emulator and it does not ship game data.

Important scope note for nfs-mw: the code and README target the **Xbox 360 build** of the game (`default.xex`, title ID `454107D9`, PAL Spain). They do not target the PC release that nfs-mw is rewriting. Everything below is therefore about the console binary's behaviour and its fixes, not the PC executable.

## What it does

Each feature is stated as working in the README unless marked otherwise.

- **Boot, menus and free roam.** The README says it runs through the prologue into free roam. [README]
- **Audio.** Working after a fix for a decoder deadlock that previously killed sound and froze the game on return to the menu. [README]
- **Direct3D 12 graphics.** Xenos GPU translated to D3D12, with two selectable EDRAM emulation paths. The fast path roughly doubles frame rate on integrated GPUs (per README). [README]
- **Vulkan backend.** Compiles and loads but renders black on Intel; untested elsewhere. Listed as partial. [README] (patch `parche_backend.py` and `parche_vulkan_opt.py` exist in the tree [source])
- **Input.** Controller and keyboard. [README]
- **V-sync and frame limiting.** Via a local patch. [README] (patch `parche_presentador.py` / `parche_velocidad.py` likely; not verified in code)
- **Internal resolution scaling** up to 4x. [README]
- **Save games.** [README]
- **Multiplayer.** Not working. The Xbox Live privilege gate is reported as solved; the network layer is not. [README]
- **Launcher.** C# WinForms launcher in `tools/lanzador/`, accepts `.iso` files (CHANGELOG 0.0.2). [source for path; CHANGELOG for .iso]
- **Performance.** About 18-38 FPS at 854x480 on an Intel Iris 540 (README, single hardware report).

## How it does it

- **Recompilation, not interpretation.** `default.xex` is translated ahead of time to C++ by a code generator driven by `app/nfsmw_manifest.toml` and `app/overrides.toml`, then compiled. No JIT or interpreter at runtime. [README]
- **Runtime is ReXGlue.** Almost all fixes are in the SDK, not the game app, and compile into `rexruntime.dll`. [README]
- **Patch scripts.** Python scripts in `tools/` (`parche_*.py`) apply and revert fixes by exact text replacement in SDK source. Each anchor must match exactly once or the script refuses to change anything. Scripts are idempotent and support `--estado` (status) and `--revertir` (restore). [source for tool list; README for behaviour]
- **Example: privilege gate.** `tools/parche_privilegios.py` edits only `src/kernel/xam/xam_user.cpp` in the SDK. It adds a boolean cvar `grant_user_privileges` (default `false`, hot-reloadable) and changes the deny-all result of `XamUserCheckPrivilege_entry` so that the setting grants privilege when on. It uses no hard-coded addresses; its docstring mentions XNet ordinals `0x36` and `0x41`, which it does not patch. [source]
- **Other patched areas** (names from README): audio deadlock, v-sync, graphics API selector, Xbox Live privilege gate, EDRAM paths, resolution scaling. [README]
- **Gap list.** `app/huecos.toml` (774 entries) is generated by `tools/huecos.py` from unresolved functions. [README for count; source for script name]
- **Build pipeline.** `tools/bootstrap.ps1` builds the SDK; `EXTRAER_XEX.bat` extracts `default.xex` to `assets/`; `CONSTRUIR.bat` applies patches, rebuilds the SDK, runs codegen and compiles into `..\build release\`. [README]
- **Diagnostics.** `tools/diagnostico/`, `tools/monitorar_xsh.sh`, `tools/comprobar_dist.ps1` present. [source for names; purpose not verified]

No memory addresses or game function names are given on the README. Addresses are not documented in what was read. [README]

## How we could implement it in nfs-mw

Licence: GPL-3.0. nfs-mw is MIT OR Apache-2.0. **No code, patch text, generated output or identifiers may be copied from this repository.** Only behaviour and facts can inform the spec. Follow the spec-first process in `docs/licensing.md`.

Applicability to a clean-room rewrite:

- **Does not apply directly:** the whole recompile-and-patch approach. It exists to run the Xbox 360 binary through an SDK. nfs-mw reads the PC install (`D:\`) and reimplements the game, so there is no PowerPC translation, no Xenos GPU, no XEX, no XAM kernel. Loader-specific hacks and SDK patch scripts do not map onto our code.
- **Possibly relevant as facts:**
  - Known bugs in the original game (audio decoder deadlock on menu return, v-sync and frame pacing, EDRAM-style rendering differences). These may inform test cases, not code.
  - Behaviour of the privilege check and the resolution scaling feature as a design goal (for example, internal resolution scaling up to 4x).
  - Save game and controller/keyboard input as user-facing requirements.

Behaviours to specify (if we choose to take any of these into nfs-mw as our own features):

1. Internal resolution scaling (factor range, aspect handling, UI scaling rules).
2. Frame limiting and v-sync options, and their default.
3. Keyboard and controller input mapping, including the controller model.
4. Save-game format and migration. (Needs the PC save format from our own spec, not this repo.)
5. Audio decode and playback error handling: must never deadlock, must not stall the menu.

Data or formats needed: PC install data read through our own format crates (`libs/` format readers that take `&[u8]`, per AGENTS.md). Nothing from the Xbox XEX or manifest files is applicable.

Natural home:

- Engine-generic items (frame pacing, resolution scaling math, input abstraction, audio decode error handling): `libs/`, Bevy-free, or as an optional renderer backend leaf crate per ADR 0004.
- NFS:MW-specific items (save format, game-specific tuning): `crates/`. `crates/` depends on `libs/`, never the reverse.

Risks:

- GPL contamination if any code is read closely and reproduced. Write specs from observed behaviour and our own testing, not from this source.
- The target build differs (Xbox 360 vs PC), so any observed behaviour must be re-verified on the PC release before it becomes a spec item.
- A repository at version 0.0.x with a stated Xbox-only scope is a weak basis for specs. Verify against the game.
